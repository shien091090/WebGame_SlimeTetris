## spec-review v23 第 2 回合(企劃回應)

### 1. 按住左右鍵跨過結算與過場:完整條文
建議把「一般結算」和「任務過場」分開處理。只讓過場推翻 v22 的「沿用既有狀態」; 一般結算保留 v22 的做法, 只補上沒定義的兩種情況。這樣改過場, 不會讓熟練玩家在連續消除時覺得按著卻不動。

**(a) 一般結算(消除、重力事件、追加消除、全盤清除; 不含任務過場)**
- **結算前就按住, 一路按到解鎖**: 照 v22 沿用。連續移動的起始延遲在結算期間照真實時間繼續累計。解鎖時已累計滿 170 毫秒, 就立刻以每 50 毫秒一欄連續移動; 未滿則等剩餘時間。
- **結算中才按下, 解鎖時仍按住**: 當成在解鎖那一刻按下。立刻移 1 欄, 起始延遲從 0 起算。
- **結算前按住、結算中放開又按下, 解鎖時仍按住**: 以最後一次按下為準, 處理同上一條。
- 旋轉、硬降、軟降的按下事件照 v22 丟棄, 不補發。解鎖時仍按住的下方向鍵照常持續軟降(v22 沒寫, 一併補上)。
- **理由**: 第一條就是熟練玩家連續消除時要的「按著接著滑」, 不動它。第二、三條如果照「沿用狀態」, 按下被丟棄了、計時卻還在累計, 結果會是解鎖後直接滑過頭, 或者輕按一下完全沒反應, 兩邊都不對。改成「當成解鎖時按下」, 就和平常按一下的手感一樣。

**(b) 任務過場**
- **過場結束時仍按住的左右鍵與下方向鍵, 不管什麼時候按下的**(結算前就按住、過場中才按下、過場中放開又按下, 三種都算), **一律要先放開, 再重新按下才受理**。放開前新方塊不橫移、不軟降。
- **理由**:
  - 過場有 4~6 秒, 期間任務換了、落速也變了, 玩家在過場前的移動意圖已經不成立。照 v22 沿用的話, 新方塊一生成就滑到牆邊, 正是老闆這輪抱怨的「一按就過頭」。
  - 「要先放開」在規格裡已經用在兩個地方: 關閉開場說明時的方向鍵, 以及過場結束後的 R。這裡只是比照, 玩家學一種規則就好。
- **代價**: 玩家如果在過場中就預先按著左鍵等, 新方塊出來不會動, 要再按一次。過場本來就是一段停頓, 可以接受; 試玩時由過場中的按鍵次數順便觀察。
- **沒有納入 (b) 的情況**: 重力事件加全盤清除連在一起時, 一般結算也可能長到約 3 秒。這種情況少見, 而且玩家不是在等下一個任務, 先不比照過場; 試玩若被點名再議。

### 2. 「輕按移兩格」的埋點欄位定義
- **粒度**: 每一次被受理的左右鍵按下記一筆。範圍只算操作中的狀態(有當前方塊、非結算、非過場、非暫停)。結算與過場中的按鍵已經記在別處, 這裡不重複。
- **什麼時候開一筆、什麼時候關**: 按下時開一筆。放開時關閉。如果還沒放開方塊就鎖定、或進入暫停、或本局結束, 在那一刻截斷關閉, 並標出截斷原因。解鎖時沿用的按住(第 1 點 (a) 第一條)、以及解鎖時當成剛按下的那種(第二、三條), 都在解鎖時開一筆新紀錄, 並標出來源。
- **欄位**(時間一律用真實時間, 單位是毫秒, 整數):
  - 塊序
  - 方向(左 / 右)
  - 按下時距離本塊生成的時間(毫秒)
  - 按住時長(毫秒; 截斷的記到截斷那一刻)
  - 實際移動欄數: 成功移動的次數, 被牆或格位擋住的不算
  - 被擋次數: 嘗試移動但因碰撞失敗的次數
  - 來源: 一般按下 / 結算前就按住、解鎖時沿用 / 結算中按下、解鎖時當成剛按下
  - 結束方式: 放開 / 鎖定截斷 / 暫停截斷 / 局終截斷
- **自我校驗**: 來源是「一般按下」, 且按住時長小於 170 毫秒的紀錄, 實際移動欄數必須小於或等於 1。
- **怎麼讀**: 在「一般按下、以放開結束」的紀錄裡, 看按住時長落在 170~250 毫秒、而且移動了 2 欄的比例。這段就是「以為輕按卻移了兩格」的區間。
- **跟數值那條不用合併**: 數值要的是逐塊的決策時間, 我要的是逐次按鍵的手感, 粒度不同。兩者可以共用同一個按鍵事件來源, 數值那條「生成到最後一次橫移」也可以從這份紀錄推出來, 但兩條都照列, 讓 RD 各自直接輸出, 讀的人不用自己推。
- **資料量**: 一局約數百塊、每塊數次按鍵, 大約上千筆, 可接受。
