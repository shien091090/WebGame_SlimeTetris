- **A1**: 方塊為標準 4 格 tetromino, 4 格顏色獨立隨機。
- **A2**: 「消除整列的同顏色史萊姆」= 整列消除後, **計算該列中目標色的格子數**, 而非「整列必須同色」。原文字面讀成後者的話這個循環直接死 — 見崩壞點 1。

## (1) 這個循環要成立需要的參數

核心恆等式(後面所有推算都從這條來):

```
每方塊產出的目標色格數 = 4η / C
```
η = 堆疊效率(方塊落下的 4 格中, 最終進入「被消除行」的比例), C = 顏色數。

**重要結論: 這個值與盤面寬度 W 無關。** 因為盤面變寬時, 每方塊清行率 ∝ 4/W 下降, 但每行的目標色產出 ∝ W/C 上升, 兩者正好抵銷。所以「解鎖 → 變寬 → 更快解鎖」的經濟面正回饋**不存在**, 解鎖速度只受方塊速率與 C 控制。這是個好消息, 表示你可以獨立調解鎖經濟與盤面寬度。

## (2) 最敏感的參數

分兩個輸出目標看, 不能混為一談:

**對「單局時長」→ T_double(速度倍增週期)最敏感, 而且它幾乎是唯一決定因素。**

俄羅斯方塊沒有勝利終點, 單局時長 = 死亡時間 = T_double × log₂(v_die / v0)。解鎖經濟完全不影響玩家活多久, 只決定「死之前解鎖到第幾欄」。T_double 從 60s 調到 45s, 死亡時間直接 ×0.75(240s → 180s), 而且它會**同時**把解鎖進度壓縮, 是唯一一個動一下就牽動全盤的參數。

**對「死前的內容曝光率」→ N(每側解鎖欄數)結構上最敏感, 但 N 通常被版面美術鎖死; 實務上最敏感的可調參數是 g。**

彈性係數(總需求 = R1·(gᴺ-1)/(g-1)):

| 參數 | 一步調整 | 總需求變化 | 彈性 |
|---|---|---|---|
| N | 3 → 4 | +79% | **2.4** |
| g | 1.45 → 1.60 | +14% | 1.3 |
| C | 3 → 4 | 時長 ×1.33 | 1.0 |
| R1 | 12 → 14 | +17% | 1.0 |

**g 的意義被低估了, 這是我最想強調的一點。** 方塊速率隨時間上升, 所以目標色產出率也在上升。若 g = 1.0(需求不成長), 第 3 次解鎖會比第 1 次**更快**達成, 解鎖節奏前慢後快, 完全反直覺。要讓每次解鎖耗時大致持平, g 必須 ≈ 「一次解鎖所跨的時間內速度成長的倍率」。以 T_double=60s、單次解鎖約 30s 計, 速度成長 √2 = 1.41 → **g ≈ 1.45**。g < 1.4 會讓後期解鎖雪崩式連發, g > 1.6 則第 3 次解鎖永遠摸不到。

## (3) 建議單局時長

**目標中位數 150-180s, 硬上限 300s, 新手保底 60s。**

推算依據三條獨立收斂到同一個窗口:

**a. 速度曲線的死亡點**
v(t) = 1 × 2^(t/60), H=16。
- t=180s → v=8 格/s → 每方塊 2s 決策時間 → 休閒玩家死亡帶
- t=240s → v=16 格/s → 1s/方塊 → 已是熟練者極限
- t=300s → v=32 格/s → 0.5s 落地 → **無人能活**

也就是 T_double=60s 這一個參數就把「中位 3 分鐘、硬上限 5 分鐘」同時做出來了, 不需要額外的結束機制。

**b. 解鎖經濟走完全程的時間**(C=3, η=0.6 → 每方塊 0.8 目標色格)

| 階段 | 方塊速率 | 產出率 | 需求 | 耗時 |
|---|---|---|---|---|
| 解鎖 1 | 1.8s/塊 | 0.44/s | R1=12 | 27s |
| 解鎖 2 | 1.45s/塊 | 0.55/s | R2=17 | 31s |
| 解鎖 3 | 1.15s/塊 | 0.70/s | R3=25 | 36s |
| 單側小計 | | | 54 | 94s |
| **左右獨立計數 ×2** | | | **108** | **188s** |

到滿寬約 188s, 落在死亡中位數之後一點 — 意思是**大多數玩家死的時候差 1 欄沒解開**, 這正是你要的留存鉤子。若改成「一次消行同時計左右」, 到滿寬只要 94s, 後面 90 秒沒有任何新內容, 節奏會塌。

**c. 首次解鎖的獎勵節拍**
R1=12 在開局速率 0.44/s 下 = 27s。開局 30 秒內給第一次盤面延展, 是 web 休閒遊戲留住第一局的合理節拍。R1 若 > 15 則首解鎖推到 35s+, 偏晚。

## (4) 預見的崩壞點

**1. 「整列同色」若照字面實作 = 循環直接歸零**
W0=6、C=3 時, 一整列同色的機率 = 3 × (1/3)⁶ = **1/243 = 0.41%**。期望要消 243 行才出一行合格。以每 3s 清一行計 = 12 分鐘。W=12 時是 1/177147, 完全不可能。**這是第 1 回合必須先釐清的規格歧義**, 建議改成「計算被消行中的目標色格數」(我全篇按此假設)。

**2. 新解鎖的欄位會變成無法填補的深井 — 我認為這是最嚴重的一個**
解鎖瞬間盤面向外延展一欄, 若該欄是空的, 玩家等於憑空獲得一個「深度 = 當前堆高、寬度 1」的井。以堆高 10 推算:
- 1 寬深井只有直立 I 能填, I 出現率 1/7(7-bag)
- 填平 10 格需 3 個 I, 7-bag 下平均要等 **21 個方塊 ≈ 25 秒**
- 這 25 秒內其餘 18 個方塊 ×4 格 = 72 格堆在剩下 11 欄 → **再墊高 6.5 行**

結論: 填不完。玩家會直接放棄那一欄, 但清行門檻已經從 11 格變 12 格 → **解鎖獎勵變成淨負收益**。必須決定新欄填充規則, 建議「以當前最低堆高補等高惰性格」或「整個盤面同時下沉一行作為補償」。

**3. 窄開局的雙重懲罰, 新手可能 60 秒內連第一次解鎖都摸不到**
W0=6 時 η 本來就比寬盤面低(整理空間少), 新手 η≈0.4 → 產出率僅 0.53 格/方塊。R1=12 需要 23 個方塊 ≈ 40s, 而新手在 W=6 的窄盤面很可能 60s 內就頂到天。也就是**新手有相當比例的局是「零解鎖」**, 完全看不到這個遊戲的核心賣點。建議 t_grace = 前 30s 不加速, 並考慮首局 R1 打 7 折。

**4. 到達 Wmax 後遊戲會突然變悶**
W=6 清一行要 6 格, W=12 要 12 格。滿寬後清行頻率**腰斬**, 而且已無解鎖目標可追。玩家的正回饋密度砍半、目標消失, 同時速度還在漲。前 3 分鐘是「解鎖爬升」, 後段變成純粹的耐力賽, 體感上像兩個不同的遊戲。建議滿寬後補一層新目標(連鎖倍率、同色 combo、或開放縱向延展)。

**5. 寬度解鎖形成存活面的正回饋, 導致玩家技術的時長分佈被放大**
經濟面不會失控(4η/C 與 W 無關), 但**存活面會**: 解鎖 → 盤面變寬 → η 上升 → 活更久 → 更多解鎖。技術好的玩家滾進穩定態, 技術差的窄盤面早死。預期單局時長分佈會是長尾的, 標準差可能接近平均值本身。「2-5 分鐘」若指的是平均, 實際分佈可能是 50s 到 6 分鐘。想收窄就靠速度不封頂(見下)。

**6. 若速度設上限, 高手局會無限延長**
W=12 且玩家進入穩定態時, 只要速度封頂就永遠不死。務必讓 v(t) 無上限: v(300)=32 格/s 是天然硬牆, 這是**唯一一個成本為零、又能保證 5 分鐘收尾的機制**。

**7. 目標色的隨機指定會製造無法規劃的局**
若解鎖需求色是隨機指定且會變動, 玩家無法預先規劃堆疊。最低限度要做到: 左右兩側需求色**同時可見**且**強制不同色**, 讓玩家任何時候都有兩個可選目標, 把「連續抽不到需要的色」的壞運尾巴砍掉。

## 建議第 2 回合先定的三件事(照優先序)

1. **消行計數規則**(崩壞點 1)— 這是歧義, 不是調參, 沒定下來後面全部作廢
2. **新欄填充規則**(崩壞點 2)— 這條決定「解鎖」到底是獎勵還是懲罰
3. **左右計數是獨立還是共用**(參數 7)— 這條單獨決定單局時長是 94s 還是 188s, 是 2× 的差距

另外, η(堆疊效率)是我全部推算的輸入值, 目前是我估的。原型一跑起來, 第一件該量的數字就是它 — 休閒與熟練兩檔各量一次, 量完我把所有時長重算一遍。
