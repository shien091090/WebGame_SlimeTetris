# spec-review v1 r1 — 企劃

## 1. 定案對應檢查(缺的項目)

定案「確定要有的」7 條、「明確不做的」5 條、「留給規格階段決定的」7 條, spec 皆有明確對應, 且待定項都給了值或標註理由。以下是仍有缺口的:

- **隨機基線未定義**。定案第 6 條要求「和隨機基線對比」作為技巧 vs 運氣的客觀裁判, spec 第 59 行只寫「用於與隨機基線比對」, 沒有規定基線怎麼產生(同序列隨機放置 agent? 歷史玩家資料?)、比什麼統計量、判定門檻。這條定案等於只寫了一半。
- **單局時長目標未落地為驗收項**。定案數值方向給了中位 150~180 秒、硬上限 300 秒、新手保底 60 秒, spec 只在結束條件說「300 秒前後自然不可維持」, 參數表與埋點都沒把這三個數字列為要回收比對的指標。埋點有記錄結束時間, 但沒說要拿來對這個區間。
- **「2 階需求成長率 2.5 不可沿用到 3 階」的警告沒傳承**。定案最後一行的警示在 spec 完全沒出現。Demo 規格是後續出貨版的起點文件, 這條漏掉的代價是有人直接把 6/15 外推。建議寫進「Demo 範圍邊界」或「待定」的備註。
- **滿級兌分率的來源標註正確但分數倍率是否適用未說**(見第 2 點)。

## 2. 矛盾與未定義

- **延展的時序未定義(影響最大)**。規則寫「某階達成的當下立即延展」, 又寫惰性格補到「延展發生前、該側既有所有欄位中最低的堆疊高度」。但消行結算順序是「計段 → 累加 → 清除列 → 上方下落」, 延展到底插在「累加點數後、清除前」還是「下落後」沒寫。兩者結果差很多: 清除前的最低堆高包含即將消失的那幾列, 新欄會補進一大截惰性格。必須把延展明確定位成結算流程的第幾步。
- **「該側既有所有欄位」的範圍歧義**。是全盤所有欄, 還是只算左半/右半? 若是後者, 7 欄、9 欄這種奇數寬度下左右怎麼切沒有定義。定案留待項只問了「含不含新欄」, spec 答了這一半, 另一半反而新增了歧義。
- **兩側同時解鎖時的互相干擾**。(a) 補惰性格的基準: 左側先延展補完後, 右側的「延展發生前」是指本次結算前的盤面快照, 還是左側延展後的狀態? (b) 目標色重抽: 規則是「重抽結果排除另一側當前的目標色」, 兩側同時解鎖同時重抽時, 雙方都拿對方的舊色當排除條件, 可能抽出同一色, 直接違反「兩側目標色恆不同」。需要規定同時發生時的處理順序或聯合重抽規則。
- **單次結算最多延展幾欄未明說**。由「溢出捨棄」可以推出一側不可能一次連跨兩階, 但這是推論不是規則, 建議直接寫死「同一側每次結算最多延展 1 欄」。
- **溢出被捨棄的點數還給不給分**。「解鎖點數分數 50 分/點」與「溢出點數捨棄」相遇時的結果沒寫。
- **滿級兌分率是否吃分數倍率**。倍率那列寫「套用於消行基礎分與點數分數」, 滿級兌分率 150 分/點不在這兩個名詞裡。後段分數膨脹幅度差一倍, 影響最佳紀錄可比性。
- **生成區與頂部鎖定未定義**。結束條件只有「新方塊生成時重疊」。方塊生成在盤面第 15~16 列內還是盤面上方的緩衝區、方塊鎖定時有格位超出盤面頂端(lock out)算不算結束, 都沒寫。16 列在窄盤面下很快堆滿, 這個邊界每局都會碰到。
- **高落速下的移動粒度**。落速無上限, 300 秒時已逾 20 格/秒, 軟降還要再 ×20。沒有規定「每次更新最多下落 N 格」或連續碰撞的處理, 也沒說軟降狀態下是否仍走完整 0.5 秒鎖定延遲(規則只排除了硬降)。這會決定後段還能不能貼地微調, 是「再忍一塊」取捨成不成立的關鍵。
- **暫停沒有任何限制**。Esc 可暫停且時間不推進, 邊界只禁止「暫停期間操作盤面」, 沒禁止無限暫停看盤。玩家可以靠暫停慢慢規劃排色, 這正好汙染要驗的那題(見第 4 點)。
- **核心循環第 5 步與數值方向互相打架**。spec 寫「盤面變寬 → 排長段與求生都更容易 → 下一次解鎖更快到手」, 但定案數值方向明講「每方塊約產出 0.23 點, 此值對盤面寬度近乎免疫, 解鎖速度與寬度解耦」。兩句不可能同時成立。實際的正回饋應該是「變寬 → 更好活 → 活得久 → 累積到更多點」, 而非「單位時間產點變快」。這句若不改, 後面所有人都會照錯的因果去調參與解讀數據。

## 3. 操作對核心循環的支撐

大致夠用, 但有三個會直接影響核心取捨的缺口:

- **無踢牆 + 6 欄窄盤面是實質的手感缺口**。原地旋轉失敗在貼牆處會讓 I/S/Z/L/J 大量旋轉不能, 開局 6 欄時每一欄都算「貼牆附近」。它不只是手感問題, 而是壓縮了玩家把某色轉到特定欄位的能力 — 也就是直接扣減「有意識排色」的可行動作空間, 剛好壓在驗證問題上。spec 已列為待定並建議第一版前決定, 方向正確, 但我建議把優先級提到「Demo 可玩前必須決定, 且傾向做簡化版左右一格試位」, 理由是寧可多一點手感輔助, 也不要讓驗證結果被旋轉失敗污染成「看起來像運氣」。
- **缺「當前盤面上既有目標色相鄰段」的即時資訊**。玩家要執行「再忍一塊把段養長」, 前提是隨時知道哪些段已經接上、接多長。物件清單只有「相鄰段結算標記(消行瞬間出現)」, 等於玩家只在事後才得到回饋。要不要給即時提示是規則層決策, 兩邊都有理: 給了, 規劃門檻下降、玩家更容易表現出「有意識」, 但可能讓測到的是「工具好用」而非「玩家會排」; 不給, 測到的是純粹的玩家能力, 但新手在 3 色混雜下很可能根本看不出段, 結果偏向「運氣」。目前 spec 是「沒寫 = 不做」, 但它也沒列進不做清單, 屬於漏掉而非決定。建議製作人明確表態, 我個人傾向不給即時提示、但把「玩家是否看得出段」放進賽後口頭訪談。
- **缺重開與離開的輸入定義**。結束條件寫「結束後可立即重開一局」, 操作表沒有對應按鍵; 暫停狀態也只有 Esc 恢復, 沒有放棄本局的路徑。Demo 要連跑多局收樣本, 這個缺口每局都會卡一次。

其餘(預覽 1 塊、ghost、DAS/ARR、軟硬降、不給硬降分)都與核心循環一致, 無 hold 也已明確列為刻意不做並附理由, 沒問題。

## 4. 驗證問題驗得到嗎

**目前規格做出來的東西, 只能收到資料, 收不到結論。** 三個原因:

- **判定方法缺一半**。沒有基線定義、沒有統計量、沒有門檻、沒有樣本計畫(測幾人、每人幾局、第一局算不算)。做完 Demo 會拿到一堆段長紀錄, 然後在「這算不算比運氣好」上吵起來。至少要補: 基線用同一份形狀/顏色序列跑隨機放置 agent 跑 N 局、比較的統計量(例如目標色段長 ≥2 的每行期望數、L≥3 的出現率)、以及事先講好的判定門檻。
- **埋點量錯了東西**。現在只在消行時記錄段。玩家有意識排色但那行還沒填滿就死了, 或刻意留著不消, 全部量不到 — 而「再忍一塊把段養長」正好是定案認定的技巧核心, 現行埋點對這個行為是盲的。建議補兩項:
  - 每次方塊鎖定時記錄: 該塊各格顏色、最終落點(欄位與旋轉態)、以及鎖定前後盤面上目標色水平相鄰段總長的變化量。這個 delta 是「主動對齊」的直接指標, 不受消行時機影響, 也最容易和隨機 agent 對比。
  - 是否使用暫停、暫停總時長(用來剔除靠暫停慢慢想的樣本)。
- **訊號可能被基線淹沒**。3 色、bag 制壓變異, 隨機放置本身就會產出大量長度 2 的相鄰段(任兩相鄰格同色機率約 1/3), 技巧帶來的增量會落在基線的雜訊裡。建議不要只看「有沒有段」, 主要指標改看長段(L≥3)佔比與上面那個 delta, 這兩個對意圖更靈敏。這點需要數值同事協助決定要比哪個量, 我只提方向。

另外一個好消息: 埋點有記錄「當時盤面寬度」, 所以「變寬之後排色是否真的變容易」可以分寬度切片驗證, 這部分規格是夠的 — 前提是第 2 點那條循環因果的矛盾先講清楚, 否則資料出來會被誤讀成解鎖速度應該變快。

---

**建議下一步(依優先序)**
1. 製作人裁決延展時序、兩側同時解鎖的順序規則、生成區與頂部鎖定 — 這三條不定, 規格無法實作。
2. 改寫核心循環第 5 步的因果, 與「產點率對寬度免疫」對齊。
3. 補埋點兩項(鎖定時的段長 delta、暫停使用), 並要求驗證計畫另立一節寫明基線與判定門檻。
4. 旋轉踢牆的待定提前到可玩前決定; 即時段提示做不做請製作人表態。
5. 補重開/放棄的輸入, 以及暫停是否限次數。
